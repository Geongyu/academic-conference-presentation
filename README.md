# Academic Conference Presentation

논문·원고·그림을 근거로 **학회 구두발표용 PPTX**를 만드는 AI 에이전트 스킬입니다.
원자료 대조, 발표 노트 내장, 렌더링 후 전 슬라이드 확인을 작업 규칙으로 규정하며, 실행할 때마다 규칙 준수 여부를 검수해야 합니다.

현재 버전: **v1.1.0** · 변경 내역: [CHANGELOG.md](CHANGELOG.md) · 상세 사용법: [README.ko.md](README.ko.md) · 작업 규칙: [SKILL.md](SKILL.md)

## 이 스킬이 하는 일

| 단계 | 내용 | 산출물 |
|---|---|---|
| 1. 환경 점검 | Python 패키지, 한글 글꼴, LibreOffice를 탐색하고 상태 기록 | `preflight.json`(`--out` 지정 시) |
| 2. 근거 정리 | 원자료의 방법·결과·한계를 읽고 주장마다 출처 위치 기록 | `evidence-map.json` |
| 3. 개요 승인 | 슬라이드별 제목·근거·예상 시간을 제안하고 승인받음(명시적 생략 가능) | `outline.md`, `slide-plan.json` |
| 4. 디자인 | 선호 색상으로 팔레트를 만들고 지정된 색상 역할의 대비 검사 | `theme.json` |
| 5. 제작 | 편집 가능한 PPTX와 발표 노트 생성 | `presentation.pptx`, `presentation.speaker-notes.md` |
| 6. 검수 | 모든 슬라이드 이미지 확인 및 원자료 대조 | `presentation.pdf`(변환 성공 시), `qa-report.md` |

## 지키는 원칙

- 원자료에 없는 결과·표본 수·통계·인용을 임의로 생성하지 않습니다. 근거가 없으면 제외하거나 초안에 `[NEEDS SOURCE]`로 표시합니다. 최종본에는 미해결 표시를 남기지 않습니다.
- 연관성을 인과관계로, 내부 검증을 외부 검증으로 부풀리지 않습니다.
- 슬라이드와 노트에 모델의 판단 과정, 작업 메모, 내부 ID를 남기지 않습니다.
- 한국어 발표는 [국문 작성 지침](references/korean-writing.md)에 따라 구체적 지표 및 수치 명시, 사고과정 노출 금지, 처음 보는 동료 연구자도 이해할 수 있는 전문 문체 유지, 내부 식별자 및 미정의 약어 사용 금지 원칙을 준수합니다.
- 검수 상태는 `PASS`, `FAIL`, `NOT_RUN`으로 기록합니다. 원자료 대조나 전 슬라이드 시각 검수를 하지 않았다면 검증 완료로 표시하지 않습니다.

## 빠른 시작

사전 요구 사항: Python 3.10 이상 환경 및 파일 읽기·코드 실행이 가능한 에이전트 환경. 기본 로컬 제작 경로는 `python-pptx → LibreOffice PDF → PyMuPDF PNG`입니다. LibreOffice와 한글 글꼴은 별도 설치가 필요합니다(Windows에서는 맑은 고딕 사용 가능). 글꼴 이름을 지정했다고 해서 자동으로 설치되거나 PPTX에 임베딩되지는 않습니다.

Agent Skills 지원 도구의 안내에 따라 **폴더 전체**를 등록하세요. 자동 탐색을 지원하지 않는 환경에서는 에이전트에게 `SKILL.md`를 먼저 읽도록 요청할 수 있습니다. 단순히 파일이 존재한다고 해서 자동으로 등록되는 것은 아니며, 참조 문서와 스크립트도 함께 유지해야 합니다.

**스킬 폴더 외부에 새 프로젝트 폴더를 생성하고 해당 폴더로 이동한 뒤** 실행하세요. 아래 `<SKILL_DIR>`를 `SKILL.md`가 있는 폴더의 절대 경로로 바꾸면 같은 명령을 PowerShell과 bash에서 사용할 수 있습니다. `python`은 Python 3.10 이상 실행 명령으로 바꾸세요(환경에 따라 `python3` 또는 `py -3`).

```text
python -m pip install -r "<SKILL_DIR>/requirements.txt"
python -B "<SKILL_DIR>/scripts/preflight.py" --out "preflight.json"
python -B "<SKILL_DIR>/scripts/smoke_test.py" --out-dir "smoke-out" --render
```

결과는 현재 프로젝트 폴더에 저장됩니다. `-B` 옵션은 스킬 폴더에 Python 캐시(`__pycache__`)가 생성되지 않도록 방지합니다. `preflight.json`에서 패키지·글꼴·렌더러 상태를 확인하세요. 종료 코드가 0이라고 해서 렌더링 가능 여부까지 보장되지는 않습니다.

`smoke_test.py`는 실제 연구 자료가 아닌 3장으로 구성된 점검용 슬라이드 덱을 생성합니다. 렌더링 후 `smoke-out/rendered/slide-001.png`부터 `slide-003.png`까지 모두 열어 한글 출력, 요소 겹침, 텍스트 잘림 현상을 확인하세요. 파일이 생성되었다고 해서 시각적·학술적 검수가 완료된 것은 아닙니다. 다시 실행할 때는 새 출력 폴더를 지정하거나, 기존 결과를 대체할 경우 `--overwrite`를 추가하세요. 자동 탐색에 실패할 경우 두 스크립트에 `--font "설치된 글꼴 이름"`과 `--soffice "LibreOffice 실행 파일의 절대 경로"`를 직접 지정할 수 있습니다.

실제 발표 자료를 제작할 때는 에이전트에게 원자료와 함께 다음과 같이 요청합니다. 에이전트가 프로젝트 폴더에 전용 `build_deck.py`를 작성하며, 점검용 스크립트 자체가 논문을 발표 자료로 변환하지는 않습니다.

> 이 스킬의 SKILL.md를 읽고 첨부 논문(PDF)으로 15분 학회 구두발표 자료를 만들어 줘. 질의응답은 별도이고, 주 색상은 남색, 슬라이드와 노트는 한국어로. 결과는 별도 프로젝트 폴더에 저장하고, 전체 제작 전에 개요를 보여 줘.


## v1.1.0 개발 및 비교 실험

v1.1.0은 Claude, GPT(Codex), Gemini 3.8 Flash가 각자 검토하고, 상호 지적 사항을 코드로 재현하여 교차 검증한 뒤 역할을 분담해 수정한 버전입니다([변경 기록](CHANGELOG.md)). [검증 기록](VALIDATION.md)에는 초기 Linux 환경과 한국어 Windows 11 환경에서 점검용 합성 3장 슬라이드 덱을 시험한 내역이 기록되어 있습니다. 실제 연구 발표의 정확성이나 모든 운영체제·글꼴의 호환성을 검증한 것은 아닙니다.

별도 비교 실험에서는 동일한 지시문과 스킬을 적용하여 세 모델에 “치이카와가 인기 있는 이유”를 주제로 한국어 5장 발표 자료 작성을 요청했습니다. 원자료 논문은 제공하지 않았으며 개요 승인 단계는 생략했습니다. 그 결과 GPT는 5장, Claude와 Gemini는 표지와 본문 5장을 생성했습니다.

| 관찰 항목 | GPT (Codex) | Claude | Gemini 3.8 Flash |
|---|---|---|---|
| 근거 | 웹 열람 3건, 결론을 미검증 가설로 한정 | 웹 열람 6건, 논평의 요인과 한계를 명시 | 웹 열람 흔적 없음, 존재하지 않는 DOI·쪽수·학회명 인용 |
| 한국어 | 막연한 제목 ("관심의 단서를 제공한다") | 추상화·독자 수준 점검 통과 | 추상적 표현과 어려운 용어 |
| 자체 검수 | 문구 점검(Gate 6) 누락 | 문제 수정 후 재확인 | 모든 항목을 통과로 허위 보고 |

위 표는 별도 실험 요약 보고서(`COMPARISON.md`)의 관찰 결과를 정리한 것입니다. GPT와 Claude에서 허위 근거는 발견되지 않았으나 전수 대조 결과는 아닙니다. 모델별 1회 실행 결과이므로 일반적인 성능 순위나 실제 논문 발표의 품질을 대변하지는 않습니다. 리뷰 보고서, 실험 요약, 세 모델의 결과물(PPTX·PDF·QA 보고서)은 저장소 파일이 아니라 [Releases](../../releases)의 v1.1.0 첨부 파일로 제공합니다.

## 알려진 한계

- 검수가 모델의 자체 보고에 의존하므로, 열람하지 않은 출처나 거짓 `PASS`를 자동으로 방지하지 못합니다.
- 문구 점검 단계를 건너뛸 수 있으며, 금지 대상인 추상적 표현 패턴 목록이 아직 마련되지 않았습니다. `plan_check.py`는 승인이 생략(`waived`)된 경우에도 경고합니다. [변경 기록](CHANGELOG.md)에는 해당 항목들이 v1.2.0에서 보완될 예정으로 명시되어 있습니다.
- 자동 구조 검사를 통과했다고 해서 텍스트 넘침이나 과학적 정확성이 보장되는 것은 아닙니다. 또한 LibreOffice 렌더링 결과와 실제 발표 현장 PowerPoint의 동일한 화면 표시를 보장하지도 않습니다.
